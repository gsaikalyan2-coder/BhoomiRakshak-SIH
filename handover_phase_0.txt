PART A — PROJECT SUMMARY
--------------------------------------------------------------------------------

WHAT WE ARE BUILDING
BhoomiRakshak — "Predictive Analysis System for Early Detection of Land
Acquisition Delays". Smart India Hackathon 2026, problem statement SIH26017,
Ministry of Rural Development, category Software, theme Agriculture & Foodtech.

An AI decision-support dashboard for GOVERNMENT OFFICERS ONLY that:
  1. predicts which ongoing land acquisition projects will be delayed, BEFORE
     the delay happens;
  2. predicts WHICH statutory stage will stall (compensation / legal / R&R /
     ownership-title / administrative approval);
  3. explains every score factor-by-factor using SHAP, in officer language;
  4. prescribes a corrective action and lets the officer simulate it first.

THE NOVELTY (verified by research, see docs/research/competitive-landscape.md)
No existing Indian system does forward-looking, explained, per-project delay
prediction for land acquisition:
  - LACRRIS (DoLR)      — records Sec. 4/11/19/23/38 dates after the fact.
                          No forecasting. No dispute/objection fields at all.
  - PAIMANA (MoSPI)     — replaced OCMS-2006 in late 2025. 1,392 projects,
                          Rs 29.68 lakh cr. RETROSPECTIVE overrun reports only,
                          capped at projects >= Rs 150 cr, no parcel dimension.
                          NOTE: this is the incumbent most likely to be raised
                          by a judge. Answer: it reports the past.
  - Bhoomi Rashi (MoRTH)— digitises 3A/3D notification workflow + PFMS payout.
                          Workflow speed, not intelligence.
  - PM Gati Shakti      — GIS layers for PLANNING. Space without time.
  - PRAGATI             — manual PM-chaired escalation, months late, a handful
                          of projects per session.
  - DILRMP / Bhu-Naksha — digitises records, scores nothing with them.

C.5  BLOODLINE / SUCCESSION — IMPLEMENTATION NOTE
--------------------------------------------------------------------------------
  The user was explicit: this is an APPLICATION FEATURE, not a model input.
  It is never trained. No succession column is fed to XGBoost.
  The risk band is a DETERMINISTIC RULE, already implemented in
  generate_dataset.py::succession_risk(), to be reimplemented identically in the
  backend service so seeded data and live computation can never disagree:

    High   — any contested claim, OR claimed shares total > 105% of the parcel
    Medium — any undocumented claim, OR more than 2 heirs on one parcel
    Low    — every heirship claim documented

  Current spread: 134 High / 167 Medium / 61 Low.
  Because it is a rule it always yields a stated reason, e.g.
  "3 heir claims without documentary proof — mutation not established".
