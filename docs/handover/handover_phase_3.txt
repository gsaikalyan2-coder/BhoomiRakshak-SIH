B6. KEY DECISIONS TAKEN THIS SESSION  (all now locked)

  D1. Derived scores are APPLICATION features, NOT model inputs.
      The compensation-gap index and the litigation-propensity score are collinear
      transforms of raw columns the model already sees (compensation_gap_pct,
      title_clarity_status, legal_dispute_stage, ownership_fragmentation_index).
      Feeding them back would cannibalise the SHAP importance of exactly the raw
      drivers an officer needs named. Succession risk was never eligible — the
      PDF requires it be a rule. All three are computed, persisted per project,
      and rendered; none is trained on.

  D2. Calibration is a SEPARATE isotonic artifact, not a CalibratedClassifierCV wrapper.
      shap.TreeExplainer cannot walk an isotonic regressor. So Model A stays a raw
      booster (explainable), and the calibrator is fitted on the out-of-fold
      predictions and saved beside it. Serving does:
          p_raw = model_a.predict_proba(X)[:,1]
          p     = clip(calibrator.predict(p_raw), 0, 1)
      Isotonic is monotone, so SHAP sign and ranking are unaffected; only the
      absolute probability moves. This is what RiskExplainer.calibrated_probability
      already does — call it, do not re-implement it.

  D3. Ordinal columns are read through a str converter, not a post-hoc fillna.
      load_projects() passes converters={col: str} for the five ordinal columns.
      This is what preserves the literal "None" (Phase 1 finding 3). Do not
      "simplify" it to pd.read_csv(path) — ml/tests/test_features.py has a test
      (test_naive_read_csv_would_have_broken_it) that documents the bug.

  D4. Unknown ordinal levels RAISE, they do not silently become NaN.
      _encode_ordinals raises FeatureContractError. In Phase 3 this means a bad
      PATCH payload from the officer update form fails loudly at the service
      boundary instead of quietly scoring wrong.

  D5. Risk bands are High >= 0.70, Medium 0.40-0.69, Low < 0.40.
      Recorded in metadata.json. The Phase 4 map pin colours must use these exact
      cut points (red / amber / green) — do not invent new ones.

  D6. delay_stage class order is frozen in metadata.json["delay_stage_classes"].
      Model B outputs class INDICES. Never map them by sorting the labels;
      always read the list from metadata.
